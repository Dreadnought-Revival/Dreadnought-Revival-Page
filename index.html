How to Play

Four Steps to the Front

Own the game

You need your own copy of Dreadnought on Steam (App 835860). No game files are distributed by this project.

Dreadnought-Revival.exe · latest release · release notes & SHA-256 checksums ↗

03

Pick a server, trust its certificate

The launcher lists the available servers and picks the project's own by default. On first start it shows the server's certificate fingerprint and asks Windows to trust it, for your user only — no admin rights. Certificates you stop using are removed again after 30 days.

04

Create an account & play

Register in the launcher, hit PLAY GAME, queue for a match and fly. On Linux, run the bundled dn-launcher-linux.sh: it finds the game's Proton prefix and opens the launcher in your browser.

Dreadnought was a massive-scale space combat game — dreadnoughts, cruisers and fighters clashing across open maps — shut down with its publisher. This project is a fan-led revival: a community-operated private server that runs the completely unmodified game client against our own backend.

Everything is emulated server-side — login, hangar, inventory, market, tech tree, loadouts, contracts, career progression and matchmaking. The only thing a player installs is a replacement launcher that signs them into a server, trusts its certificate and starts the game. No game files are modified, and no game code or assets are distributed here.

Matches are played on battle servers the backend starts on demand: the original game executable run headless under Wine, one process per match, on UDP 7777–7877. Anyone can run the whole stack and list their server in the launcher.

> objective: preserve a piece of online-game history — playable, forever.

Fan-run project, not affiliated with Greybox or Yager. Dreadnought and all related assets belong to their respective owners. You need your own copy of the game client (Steam App 835860).

03 // Game Modes

Pick Your Fight

Every mode below plays a full match on the public test server — orbit drop, your own fitted ships, scores and the victory screen. Matches size themselves to who is queued.

  • Team DeathmatchStart in fighters, unlock bigger ships as you score. Turbo TDM variant included.
  • Team EliminationBest of three rounds; a lost ship sends you back out in a fighter.
  • ConquestCapture points and claim territory, played by the original rules.
  • OnslaughtDestroy the enemy command ship, with its abilities working.
  • Ceres AwakensTeam fight over tech caches that buff their collector.
  • Proving GroundsPractice against bots, with your own loadout.
  • Havoc experimentalPvE wave defence, rebuilt from the game's own rules. Not on every server.

06 // Mission Timeline

The Road Back to War

Phase 01 — Complete

Client Reverse Engineering

Hooked and decoded the UE4 client's binary protocol, catalog and session flows — building on the original Dreadnought Revival Patch SDK. Every server payload is traceable to the client's own tables.

Phase 02 — Complete

Backend Emulation

Seven Go microservices reimplement the Greybox/Yager backend: registration, profiles, inventory, market, fleets, matchmaking and the Firmament social socket.

Phase 03 — Complete

Replacement Launcher

Dreadnought-Revival.exe (Windows, WebView2) plus a Linux/Proton script: sign-in, a server list to pick from, certificate install without admin rights, news tiles, versioned releases with one-click self-update, and Play into the unmodified game.

Phase 04 — Complete

Dedicated Battle Servers

dn-dedicated starts a headless Wine battle server per match from a UDP port pool (7777–7877), waits until it is ready, and cleans up idle ones. The battle-server mod supplies what the host never received: player loadouts, scoring, bots and the end-of-match screens.

Phase 05 — In Progress

Public Playtests

Full matches in Team Deathmatch, Team Elimination, Conquest, Onslaught, Ceres Awakens and the Proving Grounds, with scores, rewards, contracts, ship XP and fair-play checks. Havoc and custom games are still being built.

Phase 06 — Queued

The Original Numbers

Replace the placeholder values with the real ones — match reward tables, career goals, research and purchase costs — from archives, wiki snapshots and gameplay footage. If you have screenshots or videos of these screens, they help.

07 // Contribute

Developers & Operators

Help Build It

This is a server for a client we cannot change — never invent data: everything the server sends must be traceable to the client's own tables or binary. Read the client's parsers before forming a theory.

  • Read the contributing guide and the client-data docs in the server repository.
  • It's a Go workspace (Go 1.24+) of independent modules — build and test inside each one: cd mmogbrain && go test ./....
  • Run the stack locally: bash scripts/setup.sh then bash scripts/start-services.sh.
  • Open issues for bugs, PRs for fixes — see open work in server issues; site fixes go through pull requests on this repo.
  • Running a community server? List it in the launcher with a pull request to serverlist.yaml.

Testers and bug reporters keep the servers alive — every playtest report matters.
